# Огляд API HelpDesk

## Призначення
Цей документ описує **умовний REST API** майбутньої серверної версії HelpDesk. Наведені endpoint’и є навчальним прикладом і не підключені до HTML-прототипу.

Базова адреса: `https://api.example.com/v1`

Формат обміну даними: JSON.

## 1. Отримати список звернень

`GET /tickets`

Повертає список заявок. Необов’язковий параметр `status` дає змогу відфільтрувати їх.

**Приклад запиту**
```http
GET /v1/tickets?status=open
Accept: application/json
```

**Приклад відповіді — 200 OK**
```json
{
  "tickets": [
    {
      "id": "HD-1042",
      "title": "Не працює Wi-Fi",
      "category": "Мережа",
      "priority": "high",
      "status": "open",
      "createdAt": "2026-11-20"
    }
  ],
  "total": 1
}
```

## 2. Створити звернення

`POST /tickets`

Створює нову заявку. Поля `title`, `description`, `category` та `priority` є обов’язковими.

**Приклад запиту**
```http
POST /v1/tickets
Content-Type: application/json
```

```json
{
  "title": "Не відкривається навчальний портал",
  "description": "Після входу сторінка залишається порожньою.",
  "category": "Програмне забезпечення",
  "priority": "medium",
  "requester": "Олена"
}
```

**Приклад відповіді — 201 Created**
```json
{
  "id": "HD-1043",
  "title": "Не відкривається навчальний портал",
  "status": "open",
  "message": "Звернення успішно створено"
}
```

## 3. Отримати одну заявку

`GET /tickets/{id}`

Повертає детальну інформацію про заявку за її ідентифікатором.

**Приклад запиту**
```http
GET /v1/tickets/HD-1042
Accept: application/json
```

**Приклад відповіді — 200 OK**
```json
{
  "id": "HD-1042",
  "title": "Не працює Wi-Fi",
  "description": "Ноутбук не підключається до мережі.",
  "category": "Мережа",
  "priority": "high",
  "status": "in_progress",
  "requester": "Андрій",
  "assignee": "Ірина"
}
```

## Коди відповідей

| Код | Назва | Значення |
|---|---|---|
| 200 | OK | Запит виконано успішно |
| 201 | Created | Нову заявку створено |
| 400 | Bad Request | Некоректні або відсутні поля |
| 401 | Unauthorized | Потрібна авторизація |
| 404 | Not Found | Заявку не знайдено |
| 500 | Internal Server Error | Внутрішня помилка сервера |

## Примітки
- У реальній системі API має перевіряти права доступу.
- Паролі та секретні токени не можна передавати у відкритому вигляді.
- Дати наведені у форматі `YYYY-MM-DD`.
